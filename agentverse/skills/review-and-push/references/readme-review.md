# A useful README check

Read the README GitHub displays and the setup documents it links to. Check these against the actual code:

- What the project does and its current limitations.
- Required runtime, packages, data, external services and configuration.
- A usable install and start/use command, with the right working directory.
- Safe example variables and instructions that keep actual keys local.
- Existing test commands, or an honest small manual check if there are no tests.

Try the most important documented command within the review budget, after inspecting what it executes. Report **verified**, **incorrect** or **not checked**, with the actual result. A declared command is not proof that startup works.

Adapt to the project: a script needs invocation and sample input/output; a library needs a usage example; a notebook needs data and run order. Do not require a website or deployment. Preserve the author's voice when correcting instructions. A clean-install trial, external link audit or browser walkthrough belongs in a deeper review when useful and requested.
